# Local ICG development

Use Node 24 and npm 12 (verified locally: Node 24.19.0, npm 12.0.2).
Run commands from the repository root. The PHP application is reference material;
it is not part of the Next.js build and does not need XAMPP to run the new app.

## Install and run

```powershell
npm ci --ignore-scripts
docker desktop start
npm run supabase:start
npm run supabase:env
npm run dev
```

Open http://127.0.0.1:3000. The current screen is a minimal ICG shell for backend
integration; the designed public pages arrive through Claude's handoffs.

`supabase:env` writes only a local API URL and publishable key to ignored
`.env.local`. It refuses to overwrite an existing file. Never place an admin,
service-role or secret key in `NEXT_PUBLIC_*` variables. No hosted project or
login to a Supabase account is required for this setup.

The pinned packages work with install scripts disabled. Supabase CLI's matching
platform binary is installed as an optional dependency: do not omit optional
dependencies. Playwright's browser is a separate explicit download:

```powershell
npm exec --offline -- playwright install chromium
```

ICG's local API uses port **55321**, database **55322**, shadow database **55320**,
and captured mail UI **55324**. These avoid another local stack using defaults.
The start script runs DB/Auth/API/mail only; Storage, Realtime, Studio, Edge
Runtime, analytics and pooling are excluded until needed. Do not stop unrelated
containers to resolve a conflict. To stop only this configured project:

```powershell
npm run supabase:stop
```

## Verify

```powershell
npm run lint
npm run typecheck
npm run test:unit
npm run test:db
npm run test:local
npm run build
npm run test:e2e
```

- Unit tests run without a database or configured credentials.
- Database tests use the pinned CLI and current local project only. A selector
  such as `npm run test:db -- foundation` maps to a known `.test.sql` file.
  Unknown selectors, paths and remote flags are rejected. SQL fixtures roll back.
- `test:local` obtains keys from local CLI status in memory, refuses targets other
  than ICG's loopback API, provisions a synthetic Auth user, exercises the actual
  browser/server factories against Auth HTTP, and deletes the user. Only Next's
  request-cookie context is replaced; network responses are real. This proves
  connectivity and token rejection, not T07's future login/session-refresh flow.
- Browser tests require a production build first. They start their own server on
  port 3100 and run at 390 px/1440 px with isolated Chromium. Screenshots and
  failure traces are ignored under `test-results/`.
- Unit and database runners were both checked with deliberate failing assertions;
  the temporary probe files were removed after detecting failure.

In the managed Codex sandbox, package downloads, Docker access and worker/browser
process spawning may require execution approval. A sandbox `spawn EPERM` is not
an application compile error. Do not disable tests to work around that boundary.

## Configuration and maintenance

- No domain migrations, persistent business fixtures or users are introduced by
  the foundation. `foundation.test.sql` creates its probe inside a rollback-only
  transaction to verify explicit grants and RLS.
- Local Auth defaults generated by the CLI are development settings, not an
  approved production sign-up policy. Do not push this configuration to a hosted
  project. Onboarding, roles and publishing decisions remain in `decisions.md`.
- The application shell builds without Supabase configuration; factory calls
  fail with variable-specific errors if configuration is missing or unsafe.
- Server cookie writes must run in a valid Next.js mutation context. Do not add
  authenticated Server Component flows until T07 supplies session refresh/proxy.
- ESLint 9 and TypeScript 6 are pinned for Next's current plugin peer ranges.
  `decisions.md` records the scoped patched-minimatch override and its removal
  condition. Do not run forced dependency upgrades without verifying compatibility.
- Preserve `design/` and read each handoff before integrating the real page.
